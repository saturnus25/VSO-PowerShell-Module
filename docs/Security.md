# Security boundaries and limitations

This module manages application files. It never changes Windows tweak state or invokes Recovery. Force never bypasses archive, ownership, path, ACL, process or adapter checks. No telemetry, Windows registry storage, task scheduler integration or installation-time execution is used.

Command preflight checks a Windows client build of at least 22000, a 64-bit host and the x64 processor architecture. It does not equate every 64-bit environment with x64: Microsoft's [Win32_Processor architecture mapping](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-processor) distinguishes x64 (9) from ARM64 (12). These are read-only CIM queries performed when a lifecycle/status command is invoked, not during module import.

Remote trust is the fixed official repository over HTTPS, bounded redirects to GitHub's documented asset infrastructure, current asset metadata and SHA-256. No OAuth token or personal credential is required. Rate limits, missing releases, download errors and missing usable digest data fail explicitly. TLS is configured on a private HTTP handler rather than changing session-wide ServicePointManager or global preferences.

Extraction validates all entry names and expansion budgets before writing payload files, creates files exclusively and never executes archive contents. Every file must belong to the known adapter inventory or its validated schema 2 data extension; a manifest cannot add executable launchers. Reparse components, UNC/device/alternate-stream paths and dangerous batch path characters are rejected. Same-volume work folders use restricted ACLs. AllUsers requires a protected parent and administrator permission. Unknown and modified files survive removal. Runtime data without per-installation ownership is preserved.

UAC uses a constant encoded program and base64-encoded JSON data. No path or user argument is interpolated as PowerShell code. The child permits only four named manager operations and their allowlisted primitive parameters. It checks every source file's pinned hash while holding read handles that deny writes/deletes through import and operation. Results use a random private directory with owner/ACL/reparse checks and distinguish UAC cancellation, child failure and success. The child explicitly uses process-scoped ExecutionPolicy Bypass so a clean Restricted session can import the pinned bootstrap. It never changes a stored execution policy or the caller's policy. Quiet cannot open UAC. A very long request fails with instructions to use an already elevated session instead of truncating the command.

An exclusive file handle serializes operations on a destination. File hashes and paths are revalidated immediately before use. Removal preflights every planned file with READ and DELETE access, rejects read-only attributes, holds handles that deny replacement, and preflights DELETE access for directories expected to become empty before deleting the first file. It prunes empty owned directory candidates without recursive deletion. Windows path checks and process checks still have bounded race windows; this is not a proof of resistance against an administrator, a compromised kernel or the account already controlling a CurrentUser installation. CurrentUser metadata is not cryptographically authenticated against its own owner. AllUsers data relies on Windows ACLs. Do not use this manager as a privilege boundary against a compromised administrative account.

Stop reads process data without executing it. CommandLineToArgvW parses arguments; PowerShell's parser inspects protected-memory wrappers as data only. PID reuse is checked with creation time and an opened process handle. Unknown wrappers, missing command-line visibility and shared terminal windows do not authorize termination. VSO7 exposes no verified graceful shutdown interface; forced termination remains explicit and risky during active mutations.

File transactions keep the old installation directory and a journal, allowing restoration on ordinary failure. They are not a filesystem-wide atomic transaction. Power loss, filesystem failure or concurrent third-party writes can leave an ambiguous state; that fails closed with a diagnostic path. Previous directories and unowned data are retained for review. A removal interrupted after some file deletions may be partial and can be retried while its receipt remains; it does not restore deleted application files automatically.

Full removal does not delete shared Recovery, Secrets, state journals, downloaded VSO utilities, untracked logs/configuration, foreign files or the running Gallery module. Doing so safely requires a future application ownership contract and explicit migration/cleanup design. Do not delete the shared Recovery authentication material manually to make an uninstall appear complete.

Report security concerns through the [official project](https://github.com/saturnus25/VSO). Sanitize installation paths, process command lines and error output before sharing; local diagnostics may contain private machine information. Public artifacts use only the identity saturnus25. Automated privacy scanning is supplemented by manual owner review.
