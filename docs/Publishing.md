# Exact package publication procedure

Public attribution is exclusively saturnus25. Publication status, approved SHA-256 and actual acceptance results are recorded in the tagged GitHub release. A CONDITIONAL candidate must not be approved for publication. The authentic Spanish Windows UI session is an explicit non-blocking exception accepted by the owner; it must remain recorded as unverified.

1. Build with `build/Build.ps1 -Package`. This performs static checks, generates native help, builds the runtime folder, normalizes NuGet identity, entry order and ZIP timestamps, audits privacy and writes `dist/SHA256SUMS.txt`. It does not import the product runtime. Identical inputs and the same build toolchain produce identical package bytes; reproducibility across different compression/runtime versions is not promised.
2. Execute the six edition/artifact combinations and manual acceptance in the disposable VM. Retain failures and sanitize public evidence. Read [VALIDATION.md](../VALIDATION.md) and [the acceptance checklist](../tests/Manual-Acceptance.md).
3. Validate the final bytes and supply the six passing NUnit XML paths: `build/Validate.ps1 -EvidencePath $sixMatrixXmlPaths`. It compares every package entry with dist, checks the exact NuGet inventory, manifest, dependencies, privacy, syntax and help, and records SHA-256 of package, reviewed project inputs and evidence in `.work/validated-package.json`. Static validation alone is also available; it cannot pass the approval gate.
4. Review the exact SHA-256 and complete all manual acceptance. Use `build/Approve.ps1 -ValidationPath .work/validated-package.json -ExpectedSha256 $reviewedSha256 -LabAcceptanceComplete -Confirm`. Approval records the package digest and validation-record digest. This local record is an operator approval record, not a digital signature or protection against an administrator forging records.
5. `build/Publish.ps1` only verifies an existing approval. It never builds, repacks, asks for a key or publishes. `build/Publish.ps1 -Publish -WhatIf` also makes no publication or secret request after verifying the approval.
6. Only with explicit owner authorization, run `build/Publish.ps1 -Publish -Confirm`. The secure prompt occurs after review. A shared-read file handle blocks package writes/deletion from initial validation through publication; hashes and reviewed inputs are checked again after confirmation and key entry, immediately before the official publisher.

Changing the package, reviewed sources/docs/tests/build files or evidence invalidates validation/approval. Rebuild, retest, validate and approve the new bytes. Filename and version alone never constitute approval. No publish path calls Build or Compress-PSResource.

The wrapper uses the supported [Publish-PSResource -NupkgPath](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.psresourceget/publish-psresource) API. PSResourceGet is a developer dependency only. A transient plaintext string is required by its API; the wrapper never logs or persists the key and zeroes its unmanaged conversion in finally. Never put keys in history. No API key is needed for preparation tests.

The owner must verify Gallery name ownership/availability and any desired Authenticode signing. Neither package SHA-256 nor the embedded distribution manifest establishes an independent author signature. Subsequent Gallery versions require an intentional manifest/version update, preserving the module GUID.
