# Isolated Windows acceptance — not executed during development

Use only a disposable authorized Windows 11 x64 VM, with a checkpoint and no developer-PC shared installation or Recovery directories. Do not run this checklist on the development PC. Source and dist imports must be tested separately under Windows PowerShell 5.1 and PowerShell 7.x (including 7.6). Install Pester 5.7.1 in the VM if required; the runtime module has no Pester dependency.

Record the exact module/package hash, edition/version, virtual Windows build, actual outcome and sanitized failure evidence. No item below is premarked as passed.

- Run tests/Invoke-LabTests.ps1 -IsolatedLab against source and dist in each edition. Repeat with EnableNetwork only when network inspection is authorized. Mocks prove contracts, not actual installer acceptance.
- Check import in non-elevated/elevated sessions, no profile execution, no questions/network/graphics/state creation, the eight exports, and no change to session preferences.
- Exercise Help-VSO in es/en/fallback and Get-Help -Full/-Examples with English and Spanish UI culture in fresh sessions. Confirm every parameter and example is visible.
- Preview every mutating command with WhatIf, including multiple-installation selection, absent/corrupt installation, Full reset and backups. Compare filesystem snapshots: no locks, temporary directories, registrations, windows, elevation or deletions may be created.
- Install CurrentUser latest stable and explicit 1.0.0/1.2.2 into fresh VM folders. Test spaces, apostrophes and Unicode. Run the manager from System32 and confirm the default destination stays in LOCALAPPDATA Programs.
- Exercise interactive scope/default-folder choices, Enter defaults, cancellation and a graphical folder picker in STA. In MTA verify the documented console fallback. Quiet must never open dialogs or UAC; ambiguous decisions must fail.
- Test AllUsers default/custom protected parent in a non-elevated session: grant UAC, reject UAC, and try a different administrator account. Confirm parameters and structured results survive safely; no partial installation is left by cancellation. Test already elevated execution without another UAC request. Unsafe parent ACLs must fail rather than be relaxed.
- Launch only by Start-VSO and the official batch in classic console and Windows Terminal, with and without the Terminal package. Confirm Windows PowerShell host selection and upstream startup-integrity/elevation behavior. Do not apply a tweak merely to validate launching. Inspect actual process evidence and duplicate-instance detection.
- Have unrelated PowerShell, cmd and Terminal sessions open. Stop WhatIf must show only attributable VSO PIDs. Normal Stop must report the clean-shutdown limitation. Force must never target unrelated hosts/tabs. Test inaccessible command lines and PID reuse; an ambiguous host must not be killed. Do not force termination during a real mutation/Recovery operation.
- Update a closed VSO7 from 1.0.0 to 1.2.2, with sentinel foreign files, local reports/config and backups. Verify preservation and retained previous copy. Try the same version, explicit downgrade with Force, unknown format/generation and app-open update refusal.
- Simulate interruption at download, staging, old-directory rename, promotion and registration. Confirm old-copy rollback or fail-closed journal diagnostics without lost original data. Use only disposable fixture data when injecting failures.
- Preview and perform normal/Full reset in fresh fixture/application installations, including unknown and modified files and a junction. Compare the exact deletion list. Shared ProgramData Recovery/Secrets and foreign files must remain intact. RemoveBackups requires explicit acknowledgment and must delete only owned unchanged application copies. Confirm this does not restore any Windows tweak.
- Audit source, clean dist and every nupkg entry. Inspect author/company/copyright/nuspec/core properties and any icon/resources. Supply known private identity terms to the privacy audit without saving them. Inspect runtime logs/results privately for accidental secrets.
- Verify ordinary application launch works offline after a managed installation. Test GitHub outage, rate limiting, missing release, unusable digest, corrupted ZIP, traversal, duplicate case paths, link entries, oversize/expansion limits and hash mismatch. Force must not bypass them.

Do not publish if a required test fails or remains unexecuted. Preserve failed transaction folders for diagnosis; do not erase application Recovery to make a test pass. VSO8 requires its own inspected published distribution and new acceptance before claiming support.
