# Validation — VSO 1.0.1

This patch shortens the package description and capitalizes the installation examples. Runtime application management behavior is unchanged; release identity, User-Agent version and license link target are updated. The published VSO 1.0.0 package remains immutable. The GitHub release records the new package SHA-256 and actual acceptance; package documentation cannot contain its own digest without a circular hash.

VSO 1.0.0 completed the Desktop/Core × source/distribution/extracted-package matrix with 940 passing cases, zero failures and two intentional source-inventory skips. It was published to Gallery with the exact approved bytes, then installed and verified from Gallery under PowerShell 5.1 with PowerShellGet and PowerShell 7 with PSResourceGet. Both checks confirmed eight exports, native/explicit Spanish help, discovery from System32, WhatIf and all 42 installed package-file hashes. These historical observations do not replace 1.0.1 package acceptance.

The 1.0.1 candidate requires a fresh six-combination matrix and exact-package validation/approval. Build, Validate, Approve and Publish are separate; any changed bytes or reviewed inputs invalidate the previous approval. Earlier real six-version VSO7 lifecycle and fault campaigns remain applicable evidence for the unchanged manager behavior, with their original failures preserved privately. Synthetic tests do not prove every possible Windows failure timing.

Authentic Spanish Windows UI remains unverified and explicitly non-blocking by owner decision. Explicit Spanish messages, help and MAML have separate tests. Windows 10, Windows Server, ARM64 and VSO8 are not certified. Schema 2 uses synthetic distributions. Host verification is static only; runtime import, installation, removal and UAC belong in the authorized disposable VM. No Windows tweaks are executed by this campaign and no performance benefit is inferred from configuration state.
