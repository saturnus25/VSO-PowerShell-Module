# Validation — VSO 1.0.2

This release changes query UX and generated help. It preserves the installation, update, launcher, termination and removal implementations, existing ShouldProcess boundaries, transaction/receipt ownership, shared Recovery protection and source-available license. Registration, default-folder and explicit-path probing preserve access errors instead of interpreting them as absence. Published versions 1.0.0 and 1.0.1 remain immutable.

Acceptance requires a fresh Desktop/Core × source/distribution/extracted-package matrix, targeted English/Spanish status and help checks, and local repository installation/import/removal under PowerShellGet and PSResourceGet. Package inventory, XML, UTF-8/BOM, attribution, privacy, exact file hashes and six distinct Pester reports must be verified before exact-byte approval. Build, Validate, Approve and Publish remain separate. Any changed bytes or reviewed inputs invalidate approval. Actual campaign counts, hashes and failures are recorded outside the package so they cannot imply acceptance before testing or create a circular package digest.

VSO 1.0.0 previously completed the six-combination matrix with 940 PASS, zero FAIL and two intentional source-inventory SKIP results, followed by real Gallery installs in both PowerShell editions. Version 1.0.1 completed its pre-publication matrix and local installs; its public bytes and metadata were verified, while repeat post-publication VM installs were blocked and not executed. These historical results do not replace 1.0.2 acceptance. Earlier six-version VSO7 lifecycle and fault campaigns remain evidence for unchanged application-management paths, with original failures retained privately.

VSO 1.0.2 was published to GitHub and [PowerShell Gallery](https://www.powershellgallery.com/packages/VSO/1.0.2) on 2026-10-17 with the owner's authorization. The six-combination acceptance matrix completed with **1138 PASS, 0 FAIL and 2 source-inventory SKIP** results. Six language checks, two real CIM process-attribution checks using harmless waiting scripts, and two local-repository installations passed. Post-publication installations from Gallery also passed under Windows PowerShell 5.1.26100.9711 / PowerShellGet and PowerShell 7.6.7 / PSResourceGet, including discovery from System32, eight exports, native and Spanish help, localized absent status, WhatIf, all 44 installed file hashes and module removal.

The approved, GitHub and Gallery packages are byte-identical: **116705 bytes**, SHA-256 `4b41bab193d2954cd988b5d0a088c1bf7f1dcb4ae55365243a2ef96a25e07463`. The [release and verification attachment](https://github.com/saturnus25/VSO-PowerShell-Module/releases/tag/v1.0.2) record detailed results and retained failure history. The v1.0.2 tag and published package retain their pre-publication validation document; this documentation update on main records completed publication without rebuilding the package.

Authentic Spanish Windows UI remains unverified and was accepted as non-blocking; explicit languages, MAML and controlled thread UI cultures were tested. The full historical GUI/UAC/application lifecycle campaign was not repeated for this UX patch. Windows 10, Windows Server, ARM64 and VSO8 are not certified. Schema 2 uses synthetic distributions. Host verification was static only; runtime imports and dynamic operations ran in the authorized disposable Windows VM. No tweaks were executed and no performance benefit is inferred from configuration state.
