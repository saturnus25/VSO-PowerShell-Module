# Validation — VSO 1.0.2 candidate

This candidate changes query UX and generated help. It preserves the installation, update, launcher, termination and removal implementations, existing ShouldProcess boundaries, transaction/receipt ownership, shared Recovery protection and source-available license. Registration, default-folder and explicit-path probing preserve access errors instead of interpreting them as absence. Published versions 1.0.0 and 1.0.1 remain immutable.

Acceptance requires a fresh Desktop/Core × source/distribution/extracted-package matrix, targeted English/Spanish status and help checks, and local repository installation/import/removal under PowerShellGet and PSResourceGet. Package inventory, XML, UTF-8/BOM, attribution, privacy, exact file hashes and six distinct Pester reports must be verified before exact-byte approval. Build, Validate, Approve and Publish remain separate. Any changed bytes or reviewed inputs invalidate approval. Actual campaign counts, hashes and failures are recorded outside the package so they cannot imply acceptance before testing or create a circular package digest.

VSO 1.0.0 previously completed the six-combination matrix with 940 PASS, zero FAIL and two intentional source-inventory SKIP results, followed by real Gallery installs in both PowerShell editions. Version 1.0.1 completed its pre-publication matrix and local installs; its public bytes and metadata were verified, while repeat post-publication VM installs were blocked and not executed. These historical results do not replace 1.0.2 acceptance. Earlier six-version VSO7 lifecycle and fault campaigns remain evidence for unchanged application-management paths, with original failures retained privately.

The 1.0.2 release is prepared locally for owner review. No push, tag, GitHub release, Gallery publication or publication credentials are used by this iteration. Authentic Spanish Windows UI is a separate unverified limit; explicit languages, MAML and controlled thread UI cultures can be tested independently. Windows 10, Windows Server, ARM64 and VSO8 are not certified. Schema 2 uses synthetic distributions. Host verification is static only; runtime imports and dynamic operations belong in the authorized disposable Windows VM. No tweaks are executed and no performance benefit is inferred from configuration state.
